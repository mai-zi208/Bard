# 场景讲解配音模块实施方案

> 2026-11 更新：本文档已按实际落地实现修订。原方案中的 yovoice + IndexTTS 本地 GPU 部署路线已被豆包（火山引擎）云端 TTS 取代，不再依赖显存与同机部署；小程序目录已由 `miniprogram/` 更名为 `web/`。

## Context

后端生成流程的配音能力已上线：文稿定稿后调用豆包语音合成（V3 HTTP 单向流式）逐幕生成讲解音频，PCM 流补 WAV 头后经 ffmpeg-static 转 44.1kHz 单声道 64kbps MP3，发布到 CDN。已定稿并落地的产品决策：

- **3MB/2MB 包体闸门不改**。音频不进包目录，发布到 `cdn/audio/{packId}/scene-{id}.mp3`（fastify-static 根路径暴露 cdnDir，URL = `CDN_BASE/audio/{packId}/scene-x.mp3`），天然不占包体额度、不进 manifest。
- 音频元数据（durSec/bytes/sha256）写入 content.json → pack.json 的 scene.audio 字段；小程序按 pack.json 自校验 sha256。
- 小程序默认按幕流播远程 MP3；支持按包下载音频到本地（存 `USER_DATA_PATH/audio/{packId}/`，独立于包目录，避免包更新换入时被清掉）离线播放。
- 配音失败不阻塞发布：单幕失败则该幕无 audio、按钮显示「暂无讲解」；全部失败整包正常发布。
- 单幕时长 >90s 判该幕失败（`TTS_MAX_SEC`，防 TTS 拖尾复读）；单次合成请求超时 60s（`DOUBAO_TTS_TIMEOUT_MS`）。
- **讲述人音色**：包内有人物讲述人时按 voice-cast 表分配贴合身份的豆包官方音色，无人物用环境配置的默认音色。
- **前台 N 幕 + 后台补齐**：`AUDIO_EAGER_SCENES` 控制主任务同步配音的幕数（0 或缺省为全量），其余幕发布后由后台补齐任务串行合成并升版重新发布（`AUDIO_TOPUP=0` 可整体暂停）。

## 实施步骤（已落地）

### ① 后端端口与 provider

- `server/src/domain/ports.ts`：`VoiceSynthPort { enabled; synthesize(text, options?: {speaker}): Promise<{mp3, meta: SceneAudioMeta} | null> }`；`SceneAudioMeta = {durSec, bytes, sha256}`；`PackSourceInput.sceneAudio?: Map<string, SceneAudioMeta>`。
- `server/src/infra/providers/doubao-provider.ts`：
  - 流程：`POST {DOUBAO_TTS_URL}`（V3 单向流式，headers 带 `x-api-key`/`x-api-resource-id`，body 请求 44.1kHz 裸 PCM）→ 流式响应逐块解析 `{code,message,data}`，base64 拼音频，收到结束码 20000000 收尾 → 按 PCM 字节数精确算时长（不解析 MP3 帧）→ `pcmToWav` 补 RIFF 头 → ffmpeg-static 转 64kbps 单声道 MP3 → 返回 `{mp3, meta}`。
  - 人物音色可能因账号权限或下线不可用：指定 speaker 失败后自动退回默认音色重试一次，仍失败返回 null 降级为无音频，不抛错。
  - fetch 与转码函数构造注入（便于单测）。
- `server/src/infra/providers/audio-encode.ts`：`encodeMp3`（ffmpeg spawn，pipe 进出，44.1kHz/单声道/64k）与 `pcmToWav`。

### ② 管线插入

- `server/src/infra/pipeline/generation-pipeline.ts`：
  - 配音分支与出图、立绘分支并行，分支内逐幕串行合成；取词为正文按空行拆块拼接（`sceneVoiceText`，v1 旧文稿退回 `narration`）；讲述人经 `domain/services/voice-cast.ts` 的 `resolvePersonaSpeaker` 解析音色。
  - 合成落 `cdn/audio/.tmp-{packId}/`，元数据随 `sources.write` 传入；`assembler.run` 成功后 `publishAudio` 换入 `cdn/audio/{packId}/`（旧目录备份 `.old-{packId}`），换入失败则本版本不发布音频；失败/回滚时 `cleanupAudioTmp` 清暂存。
  - `run()` 与 `runVariant()` 均按 `eagerLimit()` 只同步生成前 N 幕，返回 `pendingAudio` 标记；`voice.enabled` 为 false（未配 API Key）时整个配音阶段跳过，正常发布。
  - `topUpAudio(packId)`：后台补齐入口，回读 packs-src 的 content.json，把「有正文没音频」的幕补完，写回元数据并重新装配发布（版本 +1）。
- `server/src/domain/services/task-service.ts`：主任务 `pendingAudio` 时排后台补齐任务（受队列上限约束）；`AUDIO_TOPUP=0` 时不入队、已排任务直接置失败。
- `server/src/infra/storage/pack-source-writer.ts`：scene 项写入 `audio` 元数据字段。

### ③ 装配透传

- `tools/assemble-pack.js`：`buildPack` 透传 `scene.audio`；重装时按 scene id 保留旧 `audio`（content.json 没写 audio 不代表已发布音频不存在，防重装丢元数据）。

### ④ 校验与清理

- `tools/validate-pack.js`：目录扫描按 pack.json 存在性过滤，`cdn/audio/` 不参与包校验。
- `server/src/infra/storage/pack-cleaner.ts`：删除包时同步清理 `cdn/audio/{id}` 与 `cdn/audio/.tmp-{id}`。
- `tools/build-manifest.js`：manifest 统计 `audioCount`（各幕含 audio 的数量），供小程序判断音频是否过期需更新。

### ⑤ 小程序播放

- `web/core/loader.js` `sceneAudio`：产出 `{durSec, bytes, sha256, localPath, remoteUrl}`——本地文件探测优先，`CDN_BASE` 留空且无本地文件时视为无音频。
- `web/core/audio.js`：全局单例 `wx.createInnerAudioContext`，同幕再点停止、换幕停旧播新，状态回调驱动按钮「收听讲解/停止讲解」。
- `web/components/scene/`：`onAudioTap` 接入播放；`active` 切幕时 stop；wxml 按 `scene.audio` 判定按钮可用性（无音频显示「暂无讲解」置灰）。

### ⑥ 小程序离线下载

- `web/core/cache.js`：独立 storage key `packs:audio`（不混入 packs:local）；音频目录 `USER_DATA_PATH/audio/{id}/` 与包目录分离；`downloadAudio` 按 bytes/sha256 逐幕校验；音频版本与包版本不一致时自动作废清理；`removeAudio`/删包同步清理。
- `web/pages/packs/`：已下载包行提供音频下载/删除 chip（`toggleAudio`）；`autoSaveAudio` 在列表加载后静默把音频存到本地；manifest `audioCount` 大于本地音频数时标记包「可更新」（staleAudio），走包更新补齐。

### ⑦ 配置与运维

- `server/src/config.ts`：`doubaoConfig { url, apiKey, resourceId, speaker, sampleRate, speechRate, maxSec=90, timeoutMs=60000 }`，读 `DOUBAO_TTS_URL / DOUBAO_TTS_API_KEY / DOUBAO_TTS_RESOURCE_ID / DOUBAO_TTS_SPEAKER / DOUBAO_TTS_SAMPLE_RATE / DOUBAO_TTS_SPEECH_RATE / TTS_MAX_SEC / DOUBAO_TTS_TIMEOUT_MS`；`generationConfig.eagerAudioScenes`（AUDIO_EAGER_SCENES）、`generationConfig.audioTopUp`（AUDIO_TOPUP）。配了 API Key 即启用，留空流水线跳过配音。
- `server/src/index.ts`：注入 DoubaoProvider，启动日志打印配音启用状态与后台补齐开关。
- 运维脚本：`npm run tts:check`（音色连通性自检）、`npm run audio:backfill -- [包ID...]`（给存量包补配音，不带参数处理全部缺配音的包）。
- `server/package.json`：依赖 `ffmpeg-static`。

## 验证

1. 单测：`doubao-provider.test.ts`（fake fetch 覆盖正常/失败/超时/音色回退；>maxSec 判失败）；`generation-pipeline-audio.test.ts`（装配失败不污染 `cdn/audio/{id}`、eager 幕数与 pendingAudio 标记、topUpAudio 补齐升版）。
2. `npm test`（server）+ `node tools/validate-pack.js --dir cdn` 全量通过（验证 audio 目录过滤）。
3. 端到端：`.env` 配好 `DOUBAO_TTS_API_KEY` → 小程序提交生成新地名包 → 检查 pack.json 各幕 audio、`/audio/{id}/scene-x.mp3` 可访问、游览页按钮可播；离线（断网）验证已下载音频仍可播；删包验证 `cdn/audio/{id}` 与 `packs:audio` 同步清理。
4. 回归：不配 `DOUBAO_TTS_API_KEY` 启动后端，生成流程与配音上线前完全一致（无音频发布）。
5. 存量包：`npm run audio:backfill` 批量补配音后，小程序端列表出现「可更新」提示并自动持久化新音频。

## 风险点

- 刷新失败致音频与旧 pack.json 不一致 → 暂存 `.tmp-{id}` + 装配成功后换入，换入失败本版本不发布音频。
- ffmpeg-static 安装需外网下载二进制 → 部署新机 `npm i` 后先跑 `tts:check` 验证转码链路。
- 豆包并发/配额限制 → 分支内逐幕串行合成；`AUDIO_EAGER_SCENES` 控制主任务同步幕数，其余后台补齐不占用户等待路径；`AUDIO_TOPUP=0` 可紧急暂停。
- 官方音色下线或账号无权限 → provider 自动退回默认音色重试一次，仍失败该幕降级为无音频，不阻塞发布。
- 后台补齐升版后客户端缓存 → manifest `audioCount` 驱动 staleAudio 更新提示；小程序 `remote.js` 对 manifest 有 5 分钟缓存，列表加载需 force 绕过。
