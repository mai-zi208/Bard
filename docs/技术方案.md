# 游览向导小程序 · 技术方案

| 项目   | 内容                                          |
| ---- | ------------------------------------------- |
| 文档版本 | v1.44                                       |
| 状态   | 已落地，随代码同步                                   |
| 适用范围 | 微信小程序端 + `server/` 生产端                      |
| 核心约定 | 内容与代码分离；内置 Demo + CDN 在线双轨；资源包共享 |

***

## 1. 产品与架构

### 1.1 定位

以「资源包」为内容单位的场景向导，不预设场景类型。一个包只讲一处真实地方——景点只是其中一种，任何值得介绍的空间都可以成为资源包。用户按预设路线逐幕游览，后续通过浮窗承接提问与指引——怎么走、周边有什么、去哪吃、怎么吃。

典型用法（仅作举例，不构成类型限定）：

- **陌生地方**：跟着讲解逐幕走完，快速建立整体印象；
- **日常场所**：熟悉环境、找到目的地、吃对地方。

### 1.2 核心设计

**内容与代码分离。** 资源包是纯数据（JSON + 图片），小程序只是通用分镜播放器。由此得到三点：

1. 新增景物 = 新增一个文件夹，不改渲染代码；
2. 资源包可由第三方制作，可独立分享；
3. 渲染与内容解耦，规范可独立演进。

### 1.3 用户流程

```
打开小程序 → 欢迎动画（可跳过）→ 资源包列表
  → 游览页（上下滑动切幕：主图 + 单页正文）
  → 结束页 → 返回列表
资源包页输入「景点-人物」→ 同名已下载包直接置顶，不提示已下载
  → 无对应包时提交生成，母本按「景点-导游」生成，再加工人物变体
  → 显示阶段与进度 → 完成后可游览
```

游览时可唤起浮窗，直接提问或取用指引（怎么走、周边有什么、这处讲的是什么），不打断当前幕。

### 1.4 系统架构

```
小程序（只渲染，不生成）
  ├── 内置包 miniprogram/packs/          随版本发布，冷启动兜底
  ├── 在线包 CDN cdn/{id}/               拉 manifest.json 比对后下载
  └── 任务接口 POST /tasks、GET /tasks/{id}
              ↓
生产端 server/（Fastify + TypeScript + SQLite）
  检索 → 路线规划 → 文稿 → 配图 → 母本装配 → 人物变体 → 发布
  ├── packs-src/{id}/   生成源，同景点同讲述人复用/原地覆盖（仅半成品重名加 -2/-3）
  ├── cdn/{id}/         发布物，事实来源
  ├── cdn/manifest.json 全局清单
  └── SQLite            仅存任务与索引缓存，可重建
```

边界：客户端不直连模型与 MCP，不解析生成过程；CDN 只承载静态发布物，无业务逻辑。

### 1.5 工程结构

```
miniprogram/
  pages/launch/         欢迎动画（全屏、可跳过）
  pages/packs/          资源包列表（在线 / 已下载 / 下载中）
  pages/tour/           游览页
  components/scene/     单场景五层渲染
  components/markdown/  轻量 Markdown 渲染（标题、段落、图片、引用、列表、加粗）
  components/route-bar/ 顶部路线进度
  core/loader.js        解析、校验、版本比对
  core/registry.js      构建期生成的静态索引（小程序不能动态 require 目录）
  core/cache.js         下载、落盘与淘汰
  core/preload.js       下一幕预热
  packs/                内置包（每个包是一个资源分包 packs/{id}）
  covers/               列表封面缩略图（主包，≤80KB/张）
```

职责：`pages/*` 只管生命周期与跳转；`components/*` 只管渲染，不发起网络请求；`core/*` 不依赖页面；页面不直接读 JSON，一律经 `loader.js`。

### 1.6 关键决策

| 编号  | 决策                   | 取舍                                                        |
| --- | -------------------- | --------------------------------------------------------- |
| D1  | 竖向 `swiper` + 分层入场动效 | 覆盖主要观感，兼容与性能最稳                                            |
| D2  | 内置 Demo + CDN 在线双轨   | 内置保证首屏有内容，CDN 保证内容增长                                      |
| D3  | 可视化编辑器只做本地内部工具       | 先以真实内容验证规范；编辑器只读写生成源，校验通过才发布，不做在线协作与权限                    |
| D4  | 资源包不打包 zip           | 小程序无解压能力                                                  |
| D5  | 首个 Demo 为洛阳白马寺 8 幕   | 中轴线动线清晰，史实纵深足够                                            |
| D6  | v1 不做地图导航            | 游览顺序由 `scenes` 数组表达即可                                     |
| D7  | 规范预留多语言，Demo 仅中文     | 字段结构一次定好，后续只补语言键                                          |
| D8  | 白马寺由武则天讲述            | 与洛阳、白马寺有可考关联；须守住「非建寺者」边界                                  |
| D10 | 生成端自动产出资源包           | 用户提交主题即可出包，客户端不感知生成细节                                     |
| D11 | 景点-导游母本 + 人物变体       | 同景点只生成一份母本；人物变体按 `topic + persona` 缓存，同一人物全用户共享；不做按用户画像定制 |
| D12 | 正文单页 Markdown        | `scenes[].body` 承载整幕全文，可内嵌图片；渲染端不再分屏、不再按块拆分（生成端仍按固定 4 块写作，见 §2.3）                 |
| D13 | 长文同版式上拉              | 默认露出前 3 段，上拉时正文窗口随手指变高、正文继续上移，剩余文字以同一版式被拉出来；不切阅读模式、不用按钮文案 |
| D15 | 浮窗问答只用本地检索           | 客户端不直连模型；答案取自包内正文与幕顺序，包内未收录的类目明确说明没有，不编造                  |

### 1.7 数据流

```
manifest.json → 列表页（标题、封面、状态）
    ↓ 用户选择
pack.json → scenes[] → tour 页取当前幕 → scene 组件 → markdown 组件渲染 `body`
    ↓
preload 预热下一幕图片（并发 ≤2）
```

## 2. 资源包规范

### 2.1 目录结构

```
packs/baimasi/
  pack.json              描述文件（必需）
  cover.jpg              列表封面（必需）
  body/01-shanmen.md     第 1 幕正文（Markdown）
  imgs/01-shanmen.jpg    第 1 幕主图
  imgs/01-shanmen-02.jpg 正文内嵌图
  narrator/
    wu-default.jpg       讲述人立绘（3:4 卡面）
    wu-point.jpg
  sources.md             史实来源
  images.json            配图来源与原始尺寸（生成包）
```

正文中的图片一律使用相对路径（如 `imgs/01-shanmen-02.jpg`），由 `loader.js` 在解析时重写为本地缓存或 CDN 地址；禁止绝对路径与外链。

命名规则：两位幕序号前缀，全小写、连字符，不使用中文与空格；文件名为 `pack.json` 中的引用值，禁止 `../`。

### 2.2 pack.json 字段

**本地化字段**：`title`、`subtitle`、`summary`、`imageAlt`、`body`、`pois[].name`、`pois[].desc`、`pois[].walk`。取值可为纯字符串/数组（默认语言），或 `{ "zh-CN": … }` 对象。回退顺序：用户语言 → `defaultLocale` → 第一个可用语言。

**顶层字段**

| 字段              | 类型            | 必填 | 约束                                 |
| --------------- | ------------- | -- | ---------------------------------- |
| `id`            | string        | 是  | 小写字母、数字、连字符，全局唯一                   |
| `schemaVersion` | number        | 是  | `1`（旧结构）或 `2`（`body` 单页）；客户端两种都支持  |
| `defaultLocale` | string        | 是  | 如 `zh-CN`                          |
| `locales`       | string\[]     | 否  | 已提供的语言，对象形态时据此校验                   |
| `title`         | LocalizedText | 是  | ≤20 字                              |
| `subtitle`      | LocalizedText | 否  | ≤30 字                              |
| `cover`         | string        | 是  | 3:4 竖版，≤200KB                      |
| `summary`       | LocalizedText | 否  | ≤60 字                              |
| `author`        | string        | 否  | ≤20 字                              |
| `tags`          | string\[]     | 否  | ≤5 个                               |
| `theme`         | object        | 否  | `{ bg, text, accent }` 十六进制        |
| `narrator`      | object        | 否  | 见下表；缺省只显示图文                        |
| `scenes`        | Scene\[]      | 是  | 5–40 个（校验硬上限）；建议 5–20，生成默认上限 10；顺序即路线        |
| `pois`          | Poi\[]        | 否  | 0–20 条通用场景点位；旧包不写即无点位，浮窗回落相邻景物     |
| `generated`     | boolean       | 否  | 生成包标记，透传为 manifest 的 `aiGenerated` |
| `refreshedAt`   | string        | 否  | 生成端写入的 ISO 时间，用于 180 天保鲜期判断；客户端可忽略 |

**narrator**

| 字段             | 必填 | 约束                                                            |
| -------------- | -- | ------------------------------------------------------------- |
| `id`           | 是  | 小写字母、连字符                                                      |
| `name`         | 是  | ≤8 字                                                          |
| `title`        | 否  | ≤12 字                                                         |
| `portraits`    | 否  | 全局人物插画；提供时至少 `default`，整包共用这一张（旧包仍可只按幕提供 `scenes[].portrait`） |
| `portraitFit`  | 否  | 置 `true` 时立绘按 `aspectFit` 完整显示（不裁切），顶边与标题顶边对齐                 |
| `portraitMask` | 否  | 置 `true` 时四边羽化溶入背景照片；透明抠图立绘不写此项                               |

**Scene**

| 字段             | 类型            | 必填   | 约束                                                                 |
| -------------- | ------------- | ---- | ------------------------------------------------------------------ |
| `id`           | string        | 是    | 包内唯一                                                               |
| `title`        | LocalizedText | 是    | ≤12 字                                                              |
| `subtitle`     | LocalizedText | 否    | ≤20 字                                                              |
| `image`        | string        | 是    | 9:16，宽 ≥1080，≤400KB                                                |
| `imageAlt`     | LocalizedText | 否    | ≤40 字                                                              |
| `body`         | LocalizedText | v2 是 | Markdown 文件路径；标题、段落、图片、引用、列表、加粗；生成端按 §2.3 的 150–170 字，客户端不限字数 |
| `images`       | string\[]     | 否    | 正文引用的图片，按顺序下载；缺省时解析 `body` 得到                                      |
| `layout`       | string        | 否    | 旧字段兼容；当前渲染端按单页 Markdown 自行排版，不再按字数推导                              |
| `narration`    | LocalizedText | 否    | 旧包遗留口播稿文本，保留但不生成、不渲染                                                |
| `transition`   | string        | 否    | `zoom-out` / `rise` / `slide` / `fade`                             |
| `holdMs`       | number        | 否    | 2000–15000，默认 6000                                                 |
| `narratorPose` | string        | 否    | `default` / `explain` / `point` / `think`                          |
| `portrait`     | string        | 否    | 旧包按幕人物插画，3:4 JPG，宽 600–900，≤90KB；优先于 `narrator.portraits`；新生成包不再写入 |
| `audio`        | object        | 否    | 讲解音频元数据 `{ durSec, bytes, sha256 }`；MP3 发布在包外 `cdn/audio/{packId}/scene-{id}.mp3`，不计包体；缺省表示该幕暂无讲解 |

**Poi**

| 字段        | 类型            | 必填 | 约束                                    |
| --------- | ------------- | -- | ------------------------------------- |
| `id`      | string        | 是  | 包内唯一，小写字母、数字、连字符                      |
| `name`    | LocalizedText | 是  | ≤12 字                                 |
| `type`    | string        | 是  | `service` / `food` / `exit` / `sight` |
| `desc`    | LocalizedText | 否  | ≤60 字；缺失只警告                           |
| `walk`    | LocalizedText | 否  | ≤40 字，如「出天王殿东侧 30 米」                  |
| `sceneId` | string        | 否  | 必须是已存在的幕 id；省略时不参与「同幕优先」排序            |

点位只服务浮窗回答，不渲染到游览页；`type: food` 用于餐饮意图，其余类型用于「周边有什么」。`sceneId` 让点位与路线关联，回答时优先给当前幕附近的点位并附跳转。装配链路从 `content.json` 顶层 `pois` 写入 `pack.json`；`content.json` 未写时保留上一版 `pack.json` 中的 `pois`。

`body` 为 v2 必填；v1 包保留 `paragraphs` / `pages` 兼容，客户端只读不写。

### 2.3 文案规范

**单幕单页**

| 项 | 规则                                                   |
| - | ---------------------------------------------------- |
| 幕 | 一个景物，一张主图；建议 5–20，生成默认上限 10（`GENERATION_SCENE_MAX` 可调），校验硬上限 40 |
| 页 | 每幕一页 Markdown，固定 4 块（2 屏 × 2 块），全幕 150–170 字（白马寺实测基准）；默认露出前 3 块，上拉拉出第 4 块 |
| 图 | 主图 1 张；正文可内嵌 0–3 张，必须与文稿内容对应                         |

一物一幕；只有遗址、无实物可看的不单独成幕，并入相邻幕一句带过。

**写作要求**

- 每幕固定 4 块（2 屏 × 2 块）：单块 30–48 字，同屏两块合计 70–90 字，全幕 150–170 字（含标点，以白马寺 8 幕实测 34–47 / 74–88 / 155–168 为基准）；
- 生成校验先按上面的区间执行；字数不达标时只把不达标的幕放宽到单块 25–50 字（同屏 60–100 字、全幕 140–180 字）重写，其余幕沿用原稿；仍不达标则记警告、按实际输出继续，字数不阻断发布，块数仍严格校验；
- 客观为主，先讲看得见的东西（位置、匾额、造像、题记），再讲年代、来历与关键事实；
- 每块只讲一件事，按「站位与实物 → 来历或象征 → 一条人事 → 短点评或关键事实」推进；第 2、3 块至少一块写「人事」（谁在这里做了什么、为什么），不堆形容词、不写空话；
- 第 1 块第一句落到能指认的实物，不得从地理概况、定义句或「规模最大」这类概括起笔；四块连读要像有人当面指着实物讲故事，不能像景点介绍牌或百科条目；
- 不写尺寸（高、宽、进深多少米）与数量清单（多少尊、多少块、多少种、多少例），年代、门洞数这类支撑叙事的数字每块至多一处；有讲述人时优先采用与其直接相关的实体与事件，整包至少两幕用上，资料没有关联就写客观事实，不得编造；
- 不写建筑形制术语（歇山、悬山、硬山、斗拱铺作）、不写历代重建年份；
- 生成端机械复核：命中尺寸数据、同块数量清单（≥2 处）、套语或「比…还…」超配额时，把问题清单回喂模型重写一次，仍不达标只记警告；提示词内置白马寺山门正例与龙门奉先寺反例；
- 允许解释名词、引一句典籍或碑文、由眼前景物延伸一条背景，再绕回实物；
- 传说必须写「相传」，与史实分开；有争议时给出主流说法与证据，不装作没有分歧；
- 主观点评约占全文两成，最多一块，必须挂在事实上；只有与讲述人有明确历史关联的幕才写本人视角，其余幕不写主观；
- 首段交代「此刻看得见什么」建立方位，但每幕开头句式不固定，不以对举短句升华收场；
- 参考 [白马寺讲解逐字稿](934952833-1-208.mp4_原文.docx) 的现场感：时间、天气、票价、动线、个人判断都可写，但不喧宾夺主。

细则见 [生成规范](生成规范.md) §4（范式样本、字数闸门、散文化、开头收尾、事实纪律、自检清单与制作示例）。

**史实纪律**

- 年代、数量、名称与史料一致，传说必须写「相传」；
- 每幕至少一条可核验事实，来源记入 `sources.md`；来源冲突时取官方或正史说法并注明分歧；
- 讲述人不得出现早于其亲历年代的表述，不得编造细节；
- 私德与争议不进讲解，只保留与景物相关的公共部分。

**口播稿（旧字段）**：新包不再写 `script.md` 或 `scenes[].narration`，讲解音频直接取 `scenes[].body` 的纯文本合成（见 §4.8）；旧包保留 `narration` 字段，客户端不渲染。以下标签表与旧的 `tools/tts.py` 分段合成方案均已停用，仅作历史参考。

标签集合固定：

| 标签            | 合成处理                                         |
| ------------- | -------------------------------------------- |
| （停顿半秒）～（停顿五秒） | 该处插入对应时长静音，允许 0.3–5 秒；支持阿拉伯数字与「半/一两三…/一点五」写法 |
| （放慢）/（加快）     | 其后文本语速 −20% / +20%，直到下一个语速标签                 |
| （加重）/（压低声音）   | 其后文本音量 +20% / −20%，直到下一个音量标签                 |
| （笑）           | 仅作提示，合成时剥离                                   |

全角括号只用于标签，出现集合外的括号内容直接报错；旧版 `tools/tts.py` 的标签解析与分段合成已随本地 TTS 一起移除，现行豆包合成不再识别这些标签。

**讲述人边界**：武则天是白马寺的见证者与扩建者，不是建寺者。寺建于永平十一年（68 年），比她出生（624 年）早约 550 年；垂拱元年（685 年）她命僧怀义重修白马寺，「寺成，自为寺主」，事见《旧唐书·外戚传》，武周时期寺院规模达到顶点。评述身后事须显式标注时间距离（「朕身后千年」），不得写成亲历；任何让她亲历 624 年之前事件的表述都属错误。

### 2.4 素材规范

| 类型    | 规格                                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------- |
| 封面    | 3:4，≥900×1200，JPG，≤200KB                                                                                            |
| 分镜图   | 9:16，1080×1920，JPG 质量 60–70，≤400KB，并受整包均分预算约束；避免大面积纯黑，注意文字叠加区                                                       |
| 正文内嵌图 | 宽 ≤1080，保持原比例，JPG，单张 ≤300KB；同一幕合计 ≤600KB，并受整包均分预算约束                                                                 |
| 讲述人立绘 | 透明 PNG，宽 360–900，≤150KB；顶边与标题顶边对齐，高度按 3:4 且不越过文字块底部；抠图轮廓外的深色/棋盘格残留须清理（取最近实心像素颜色），alpha 做 2–4px 柔和过渡，底部淡出避免裁切直边      |
| 人物插画  | 整包一张，3:4，600×800，JPG，≤90KB；人物立于景物之前，客户端 `aspectFit` 完整显示并四边羽化；旧包的按幕 `scenes[].portrait` 仍按单张 3:4、宽 600–900、≤90KB 校验 |
| 配色    | `bg` 深色、`text` 正文、`accent` 强调，正文与背景保证对比度                                                                            |

真机 `<image>` 不解析 webp：封面与分镜输出 jpg，立绘保留 png 透明底。生成包的分镜图来自检索实拍或兜底生成图，后者属写实示意，未替换为可授权实拍前须在包内标注「示意图」。

3MB 是整包上限，幕数越多单幕预算越小：按 `floor(3MB / 幕数)` 均分，30 幕时每幕约 100KB，主图优先压缩，正文内嵌图减到 0–1 张；超出时先降质，仍超出则阻断发布。

### 2.5 校验规则

发布前强制运行 `tools/validate-pack.js`。

**错误（阻断）**：必填缺失或类型不符；`id` 非法或重复；引用文件不存在；图片尺寸或体积超限；出现路径穿越；`scenes` 不在 5–40；v2 缺 `body`、v1 缺 `paragraphs` / `pages`；`body` 内图片缺失或使用外链；出现不支持的 Markdown 语法（表格、内嵌 HTML、脚注）；单幕正文 >20000 字；单幕内嵌图合计 >600KB；整包 >3MB；内置包 >2MB（超过单个分包上限）；`schemaVersion` 不在 1–2；本地化字段缺 `defaultLocale` 值或 `locales` 声明值；`pois` 非数组、超过 20 条、id 重复、`type` 非法、`sceneId` 指向不存在的幕，或 `name` / `desc` / `walk` 超出字数上限。

**警告**：缺少 `subtitle` / `theme`；单幕正文 <96 字（低于规范下限）；整幕无一张内嵌图；在线包 >2MB（内置前需再压缩）；图片格式非 jpg/png；对象形态只含一种语言。

## 3. 客户端

### 3.1 游览页结构

```html
<swiper vertical circular="false" duration="600" bindchange>
  <swiper-item><scene active direction index /></swiper-item>
</swiper>
```

每幕五层：

1. 背景层：主图 `aspectFill`；
2. 遮罩层：自上而下渐变，保证文字可读；
3. 人物层：立绘绝对定位在文字块左侧，顶边与标题顶边对齐、高度按 3:4 且不越过文字块底部，无背景框；序号、标题、副标题左内缩让开立绘；
4. 文字层：序号、标题、副标题、Markdown 正文；正文内的浮动占位让首几行窄栏，越过立绘底边后恢复通栏；
5. 操作层：`收听讲解` 按钮，有 `audio` 元数据时点击播放/再点停止，无音频时置灰显示「暂无讲解」；只在用户点击时播放，切幕或离开页面即停播。

比例：立绘宽 240rpx，标题区左内缩 270rpx；正文绕排占位同宽。

幕与幕之间左右滑动切换。每幕正文默认只露出前 3 块，底部渐隐；在正文块上拉时，窗口高度随手指增长、正文同步上移，剩余文字以同样的字号与行距被一起拉上来；窗口长到顶部界线后继续上拉，正文在窗口内继续上推，直到全文末行；下拉按相反顺序回滚。立绘全程固定在左上不动，正文上移越过其底边后由窄栏自动改为通栏，把立绘下方的空位用满。松手吸附到「折叠」或「全开」两档，不设按钮文案，也不切换到另一套阅读版式——字号、立绘、标题位置全程不变。正文未超出 3 块时不接管纵向手势，上拉仍为原有「抬起阅读」。

### 3.2 动效与降级

| 层     | 变化                           | 时长    | 延迟    |
| ----- | ---------------------------- | ----- | ----- |
| 背景图   | `scale 1.12 → 1`             | 700ms | 0     |
| 标题    | `translateY(24px) → 0` + 淡入  | 500ms | 120ms |
| 副标题   | 同上                           | 500ms | 180ms |
| 立绘    | `translateX(-24px) → 0` + 淡入 | 600ms | 200ms |
| 正文容器  | `translateY(16px) → 0` + 淡入  | 450ms | 240ms |
| 播放按钮  | `scale 0.9 → 1` + 淡入         | 350ms | 段落后   |
| 上一幕退出 | `scale 1 → 0.96`，透明度降至 0.4   | 400ms | 0     |

单幕入场约 1.3s。正文只对容器做一次淡入，不逐段错峰，避免长文元素过多。同包切幕时立绘只做 200ms 透明度过渡，不做位移。方向由 `bindchange` 比较新旧索引，容器 `data-direction` 切换位移符号。

低端机降级：`app.js` 依据 `platform` + `benchmarkLevel`（缺失时按内存 ≤2GB 判断）置 `lite`，转场 600ms → 420ms，去掉背景缩放与分层错峰，合并为 0.2s 淡入。

### 3.3 分发与缓存

| 类型  | 位置  | 更新                             |
| --- | --- | ------------------------------ |
| 内置包 | 主包  | 随版本发布                          |
| 在线包 | CDN | 比对 `manifest.json` 的 `version` |

列表状态：在线、可更新、需更新（低于 `minVersion`）、已下载、已下架（`deprecated`）、下载中（进度百分比）。

命名与生成：母本 `id` 为 `{景点-slug}`，人物变体为 `{景点-slug}--{人物-slug}`；提交时按「景点 + 讲述人」去重，已有资源包直接打开、有任务在生成则复用同一任务，不重复生成；确需重建时（刷新/编辑器）原地覆盖并 `version + 1`，历史遗留的带后缀同名包在生成成功后清理。输入「景点-人物」时如已有同讲述人的包直接复用，否则只做错别字提示（近似地名弹「是不是想找…」），确认无误仍照常生成。

- 未下载时走 CDN 直链，依赖 `<image>` 网络缓存；
- 下载（含更新）一律先写 `USER_DATA_PATH/packs/.tmp-{id}/`，清单内全部文件校验通过后才换入正式目录：旧目录改名 `.bak-{id}` → 临时目录 `rename` 为 `{id}` → 删除备份；换入失败还原旧目录，下载任一步失败只清临时目录，旧版本保持可用；
- 增量：更新时逐个比对正式目录里的同名文件与清单 `checksums`，一致就本地复制，只下载变化的文件；
- 更新判定用「版本不等」而非「远端更高」，服务端把清单回滚到低版本时已下载用户也能跟随；本地版本低于 `minVersion` 时点开先强制更新；
- `deprecated: true` 为软下架：已下载的继续离线可用、不再更新，未下载的从列表隐藏并拒绝下载；服务端回滚只需换回 `manifest.json.bak`，客户端按版本不等自动跟随；
- 清单在客户端缓存 5 分钟（`remote.cachedManifest`），`onShow` 与提交生成前都先读缓存；输入框再次提交同名景点时先确保清单就绪，本地版本落后则弹「有新版本 / 去更新」并走增量更新，不再出现绕开版本检查直接打开旧包；下架且未下载的包不参与同名匹配；
- 讲解音频不进包目录：下载资源包时自动把该包全部音频一并存到 `USER_DATA_PATH/audio/{id}/`，按 `pack.json` 的 `audio.bytes/sha256` 校验；播放优先本地文件、缺失时回退 `CDN_BASE/audio/{id}/`；包版本变化时旧音频作废，删除资源包时一并清理；列表页保留「存音频 / 删音频」用于补存或释放空间；清单为每个包附带 `audioCount`，本地包音频元数据缺失（早期下载的旧包）时按「可更新」重新下载换新；清单不可达（离线）时已下载包仍从本地 `pack.json` 读取音频并显示存音频入口；
- 记录 `lastUsedAt`，接近存储上限时按最久未使用淘汰；
- 分享路径 `pages/tour/tour?pack={id}`，未下载则直接在线模式；标题取 `title`，配图取 `cover`。

### 3.4 欢迎动画

纯 CSS + SVG 路径描边，不用视频与 Lottie。首帧即为静态封面层，在 JS 执行前完成渲染，杜绝白屏。

| 时间          | 内容            |
| ----------- | ------------- |
| 0–250ms     | 品牌色底 + 静态封面   |
| 250–1200ms  | 主体线条逐笔描出，轻微缩放 |
| 1200–2000ms | 线条扩散为画面，标题浮现  |
| 2000–2500ms | 与列表页交叉淡出      |

点击任意位置可跳过；动画期间预加载第一个包的封面；`prefers-reduced-motion` 或低端机降级为静态封面 + 淡出。

### 3.5 性能红线

- 禁用 `filter: blur`、`backdrop-filter`、`clip-path`；
- 单幕同时动画元素 ≤6 个；
- 只预加载下一幕，并发 ≤2；
- 不使用外部字体；
- 图片统一 `aspectFill`，避免重排。

## 4. 服务端

### 4.1 分层与存储

- 技术栈：Fastify 5 + TypeScript（Node 原生类型剥离，无构建）+ `node:sqlite`；
- 分层：`api/` → `domain/`（索引、清单、任务状态机）→ `infra/`（SQLite 仓储、目录扫描、装配脚本、生成流水线与外部服务）；
- 领域层只依赖 `domain/ports.ts` 中的接口；
- 磁盘是事实来源：`cdn/` 与 `packs-src/` 决定内容，SQLite 只存任务与索引缓存，删库可由扫描重建；
- 启动与每次装配后重扫 `cdn/`、重写 `manifest.json`；
- 启动：`cd server && npm install && npm run dev`，默认 8788；`PORT` / `CDN_DIR` / `SRC_DIR` / `DB_PATH` 可覆盖；
- 联调接口：`GET /health`、`GET /api/packs`、`GET /api/sources`、`POST /api/reindex`；
- `/health` 返回 `cdnReadable`（发布目录可读）、`diskFree`（所在磁盘剩余字节，取不到为 `null`）、`queueLength`（进行中 + 排队任务数），供探针发现挂载丢失、磁盘将满与队列积压；
- 装配先写 `cdn/.tmp/`，成功后整体 `rename` 换入 `cdn/{id}/`，旧版留在 `cdn/.backup/{id}/`（只保留一版）；`manifest.json` 先写 `.tmp` 再原子替换，上一版存为 `manifest.json.bak`。

### 4.2 生成流水线

| 步骤     | 产出                             | 实现                                                                     |
| ------ | ------------------------------ | ---------------------------------------------------------------------- |
| 1 检索   | 史实、年代、方位、来源                    | 百度百科移动页为主，Bing 摘要补充                                                    |
| 2 路线规划 | 可行路线 → 景物清单                    | 通义千问 `qwen3.7-plus`，沿动线排序；幕数 5–20，生成默认上限 10，硬上限 40                                  |
| 3 文稿   | 每幕 Markdown 正文 + `sources.md`  | 通义千问 `qwen3.7-plus`，整幕 `body` 固定 4 块（单块 30–48 字、同屏 70–90 字、全幕 150–170 字）；内嵌图暂不生成 |
| 4 配图   | 主图（正文内嵌图待接）                    | 全部由出图服务（千问 `qwen-image-2.1-pro`，OpenAI images 兼容）按本幕 `imageAlt` 生成，竖图 1024×1536；出图 6 路并发、单幕失败隔 2 秒重试一次，与立绘、配音并行；重试仍失败则整包失败回滚 |
| 4b 插画  | 整包一张 3:4 人物插画（指定人物时）           | 人物立于景物之前，景物只作虚化背景；写入 `narrator.portraits.default`，不再按幕产出插画；无人物则整包不生成插画 |
| 4c 配音  | 每幕讲解 MP3（包外发布）                | 豆包在线 TTS，按讲述人匹配音色；与出图、立绘并行，逐幕写 `cdn/audio/.tmp-{id}/`，装配成功后换入 `cdn/audio/{id}/`；单幕失败仅该幕无音频，详见 §4.8 |
| 5 母本装配 | `pack.json` + `body/*.md` + 素材 | `tools/assemble-pack.js`，一步完成转图、校验、清单重写                                |
| 6 人物变体 | 按 `persona` 改写正文             | 复用母本素材与配图，同一景点 + 同一讲述人原地覆盖重建（版本 +1）；无人物时跳过                                                       |

约定：

- 先生成到 `packs-src/{id}/`，校验通过后再进 `cdn/`；
- 母本目录为 `packs-src/{景点}/`，人物变体为 `packs-src/{景点}--{人物}/`；同一景点 + 同一讲述人（含无人物）只保留一个生成源，提交时已有资源包直接复用、不重复生成，确需重建时原地覆盖（版本 +1），仅半成品目录重名才追加 `-2`、`-3`；变体只写 `pack.json` 与 `body/`，图片以硬链接复用母本，不重复占空间；
- 正文 Markdown 只允许标题、段落、图片、引用、列表、加粗；内嵌图先写 `![说明](imgs/xxx.jpg)` 占位，装配时替换为实际文件名；
- 生成链路直出整幕 `body`：`script-provider` 产出 4 块纯文本段落（单块 30–48 字、同屏 70–90 字、全幕 150–170 字；字数不达标自动放宽到 25–50 / 60–100 / 140–180 重写一次，仍不达标记警告继续），校验失败时把具体原因回喂模型重写一次；`pack-source-writer` 写入 `content.json` 的 `scene.body`，装配脚本落成 `body/{两位序号}-{sceneId}.md` 并把包自动置为 `schemaVersion: 2`；已有 `packs-src` 仍是 `pages`，重新装配才转 v2；
- 人物变体不重新检索、不重新配图，只改口吻与讲述视角；史实、来源与母本一致；
- 先写 `pack.json` 再产出素材，转换脚本按引用反推源文件名；命名不一致时用 `sources.json` 声明（如 `07-qiyunta.jpg ← scene-pagoda.jpg`）；
- 转换命令：`python tools/convert-assets.py --src packs-src/{id} --out miniprogram/packs/{id}`；
- 内置包拆为资源分包后，列表封面由 `python tools/build-covers.py` 生成到 `miniprogram/covers/{id}.jpg`；
- 默认「现代导游」包不写 `narrator`，游览页按 `portraitUrl` 为空隐藏立绘；
- 资源包页输入「景点-人物身份」，客户端拆成 `topic` 与 `persona` 提交；没有人物时 `persona` 为空，讲述人为现代导游；
- 资源包页不再区分内置包与在线包：同标题 + 同讲述人的包合并为一项，同标题且在线包为默认讲述人时也并入内置包（均优先展示内置包）；带明确讲述人的包名显示为「景点·讲述人」，默认讲述人只显示景点名；内置包与已下载在线包统一显示「已下载」，未下载的在线包显示「可下载」；已下载的包在清单下线或断网时仍保留在列表中，可再次打开；
- 已下载的在线包在资源包卡片与列表项右上角显示删除按钮（内置包不显示）：二次确认后调 `cache.remove` 清掉 storage 元数据与 `USER_DATA_PATH/packs/{id}` 文件，条目回到「可下载」，需要时重新下载；
- 人物身份限 2–8 字（与 `narrator.name` 上限一致），服务端在入队前校验，超长直接返回 400，避免装配阶段才失败；
- 指定人物时生成包只绘制一张人物插画，写入 `content.json` 的 `narrator.portraits.default`（`narrator/{id}-default.jpg`），并置 `portraitFit` / `portraitMask`；不再写 `scenes[].portrait`；`tools/convert-assets.py` 按 `narrator-default.{ext}` 反查源图，按 3:4、宽 600、≤90KB 输出 JPG；
- 人物插画与同一景点的景物绑定、与幕数无关：人物立于景物之前，不再为每一幕安排不同动作与画面；
- 分镜与插画共享 2000KB 预算：指定人物时只预留一张插画的 90KB，剩余额度再推导 `sceneMaxKb`；
- 生成图接口返回占位图（固定 176626 字节、画面为「The image is generating...」）时直接判失败并提示重试，不把占位图当插画落盘；
- 无人物时 `sceneMaxKb = max(120, min(400, floor(2000 / 幕数)))`；指定人物时改用扣除插画预留后的余额；
- 同名目录不覆盖，自动追加 `-2`、`-3`，`packId` 以最终目录名为准；但提交阶段会按「景点 + 讲述人」去重，已有资源包直接复用、不重复生成，确需重建时既有生成源原地覆盖（版本 +1），因此不会产生第二个同名包，历史上带后缀的重复包在生成成功后自动清理；
- 未配置 `LLM_API_KEY` 时任务明确失败，不静默降级；文稿服务走通义千问 OpenAI 兼容接口（`LLM_BASE_URL` + `/chat/completions`），`LLM_MODEL` 默认 `qwen3.7-plus`，混合思考模型默认关闭思考（`LLM_ENABLE_THINKING=1` 可开启），思考内容不占 `max_tokens`。

### 4.3 任务接口

```
POST /tasks
  Header: x-api-token: <API_TOKEN>   （服务端配置令牌时必填）
  Body:   { "topic": "洛阳关林", "persona": "武则天" }   // persona 可为空字符串
  200:    { "taskId": "..." }

GET /tasks/{taskId}
  200:    { "status", "stage", "progress", "packId", "error" }
```

`status`：`queued` / `running` / `validating` / `done` / `failed`。
`stage`：检索资料、编排幕大纲、撰写文稿、生成配图、绘制人物插画、生成讲解音频、装配资源包、刷新清单、完成、失败。后三步（出图、立绘、配音）并行推进，客户端直接展示。配音默认全量同步生成（`AUDIO_EAGER_SCENES=0`）；若配置为只同步前若干幕，其余幕在包发布后由后台 `kind=audio` 任务补齐，全部补完再整体发布 `version + 1`。

错误码：`400` 主题为空、人物身份不合法或未通过内容安全校验；`401` 令牌缺失或错误；`404` 任务不存在；`429` 单来源限流（默认 10 次/分钟）或队列已满（`TASK_QUEUE_MAX`，默认 8）。

其他约束：

- 单工作者串行处理，800ms 轮询取任务；
- `persona` 为空或为「导游」时产出母本；其他人物先复用或生成母本，再产出变体；
- 同主题 + 同人物命中进行中任务时返回原 `taskId`（`POST /tasks` 响应只含 `taskId`）；
- 客户端 3 秒轮询；任务存档在 `packs.pendingTasks`，重进页面继续轮询，服务端 404 时移除；
- 首次生成含检索、模型调用与图片下载，通常 30–90 秒；
- `GET /metrics`（同样校验令牌）返回最近 200 条任务的状态分布、阶段耗时、失败聚合与复用率（`reused` / `reuseRate`）。

### 4.4 生成策略（同景点同讲述人唯一）

- 主题归一化：去空格、去行政区前缀（「河南省」「洛阳市」）、去「景区」后缀；
- 提交去重：`POST /tasks` 时同景点 + 同一讲述人（默认讲述人与空串同等对待）已有可下载的资源包，不再调用生成流水线，而是创建一个立即 `done` 的任务（`stage = 已存在`、`packId` 指向既有包、`reused = true`），响应仍只返回 `taskId`，客户端轮询拿到 `packId` 后直接打开；资源包包括 `miniprogram/packs/` 下随小程序发布的内置包（服务端读取 `pack.json` 的 `title` 与 `narrator.name`，同名时优先复用内置包）和 `cdn/` 下的已发布包，软下架（`deprecated`）的已发布包不参与复用；
- 同一景点 + 同一讲述人已有任务在排队/生成时，重复提交复用同一个 `taskId`，不重复排队；
- 同一景点 + 同一讲述人只允许存在一个包：确需重建时（刷新任务、编辑器发布）原地覆盖既有生成源（旧源备份、失败回滚），发布版本 `version + 1`，客户端按「版本不等」原地更新，不产生同名新包；
- 历史原因遗留的带 `-2`、`-3` 后缀同名同讲述人包，在下次生成成功后自动清理（源目录、发布目录与音频一并删除）；只有半成品目录（无 `content.json`）才会在 `createDir` 时追加后缀；
- 人物变体仍以已有母本素材为底稿：只改写正文，分镜与配图硬链接母本，不重复出图；没有母本时先生成母本；
- 不再判断保鲜期，也不会因请求命中旧包而自动入队 `kind=refresh`；历史遗留的刷新任务仍可执行：原地重新生成并保留包 id，成功后 `version + 1`，生成源先备份到 `packs-src/.refresh-backup/`，新包通过校验并发布后才删除备份，失败则恢复旧源；
- 刷新任务失败写入冷却截止时间（`PACK_REFRESH_COOLDOWN_DAYS`，默认 7 天），冷却期内不重复触发。

### 4.5 质量闸门

- 结构：未通过 `validate-pack.js` 不得发布；
- 正文：Markdown 仅用白名单语法，图片必须存在且无外链；正文与内嵌图计入 3MB 预算；
- 史实：每幕至少一条可核验来源，写入 `sources.md`；
- 配图：`images.json` 与 `sources.md` 记录来源与原始尺寸，兜底生成图标注「示意图」；
- 内容安全：`topic-guard` 在入队前校验主题（2–30 字、字符集、内置敏感词），违规 400；
- AI 标识：生成源写 `generated`，清单输出 `aiGenerated`，客户端列表与游览页展示「AI 生成」；
- 体积：在线包 ≤3MB（报错）、内置分包 ≤2MB（报错，超出需压低分镜质量）；列表封面 `covers/{id}.jpg` ≤80KB。

### 4.6 manifest 结构

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-12T00:00:00.000Z",
  "packs": [
    {
      "id": "longmen--wu-zetian",
      "masterId": "longmen",
      "persona": "武则天",
      "version": 3,
      "minVersion": 2,
      "refreshedAt": "2026-11-12T00:00:00.000Z",
      "title": "洛阳龙门石窟",
      "subtitle": "伊水两岸的千龛",
      "summary": "",
      "tags": ["石窟", "造像"],
      "total": 8,
      "narratorName": "",
      "cover": "cover.jpg",
      "bytes": 1889000,
      "files": ["pack.json", "cover.jpg", "body/01-yique.md", "imgs/01-yique.jpg"],
      "aiGenerated": true,
      "checksums": {
        "pack.json": { "sha256": "…", "size": 10661 },
        "cover.jpg": { "sha256": "…", "size": 193730 },
        "body/01-yique.md": { "sha256": "…", "size": 2048 },
        "imgs/01-yique.jpg": { "sha256": "…", "size": 199078 }
      }
    }
  ]
}
```

`files` 为包内相对路径，客户端按顺序下载；`checksums` 为逐文件 sha256 与字节数，下载后先比大小再比摘要，不符即丢弃半成品并提示失败；`minVersion` 表示客户端本地版本低于该值时必须更新才能进入（缺省视为 0，不限）；`deprecated: true` 为软下架，缺省不输出，已下载用户可继续离线使用、不再更新，未下载用户列表隐藏并拒绝下载；`refreshedAt` 供服务端判断保鲜期，客户端可忽略。清单 `schemaVersion` 必须为 1，`pack.json` 支持 1–2，其他版本拒绝渲染并退回列表。人物变体带 `masterId` 与 `persona`，素材由母本硬链接而来，`files` 仍列全量，客户端按普通包处理。

### 4.8 配音模块实施方案（豆包在线 TTS）

**目标**：为每幕生成讲解 MP3。音频不进资源包目录、不计 3MB / 2MB 包体，只由用户点击播放，并支持整包离线缓存。

**合成服务**

| 项 | 实现 |
| - | - |
| 服务 | 火山引擎豆包语音合成 2.0（`seed-tts-2.0`），HTTP V3 单向流式 `POST /api/v3/tts/unidirectional` |
| 取词 | 每幕独立请求；把 `content.json` 的四块正文拼成连贯段落（`sceneVoiceText`，旧包回退 `narration`），不做分段拼接 |
| 输出 | 请求裸 PCM（默认 44.1kHz），按流式 JSON 的 `data` base64 分片累加，`code=20000000` 结束；用字节数精确算时长，不解析 MP3 帧 |
| 编码 | `ffmpeg-static` 转 44.1kHz、单声道、64kbps MP3，保留高频，避免听感发闷 |
| 时长闸门 | 单幕超过 `TTS_MAX_SEC`（默认 90 秒）判该幕失败，防 TTS 拖尾复读 |
| 失败处理 | provider 内部捕获异常返回 `null`，不向上抛；单幕无音频只让该幕按钮置灰，不阻塞整包发布 |

**配置**（`server/.env` → `doubaoConfig`）：`DOUBAO_TTS_URL`（默认官方单向流式地址）、`DOUBAO_TTS_API_KEY`（缺省则不启用配音，其余流程照常）、`DOUBAO_TTS_RESOURCE_ID`（默认 `seed-tts-2.0`）、`DOUBAO_TTS_SPEAKER`（默认 `zh_female_gaolengyujie_uranus_bigtts`）、`DOUBAO_TTS_SAMPLE_RATE`（44100）、`DOUBAO_TTS_SPEECH_RATE`（0）、`DOUBAO_TTS_TIMEOUT_MS`（60000）、`TTS_MAX_SEC`（90）。

**人物音色**

- `voice-cast.ts` 维护「讲述人 → 官方音色」表：武则天、花木兰用女雷神；上官婉儿、李清照、甄宓用灿灿；杨贵妃、王昭君用苏菲；李白、苏轼、玄奘等男声用云舟；曹操、关羽、岳飞、汉明帝用小天；
- 未收录人物按称谓兜底：命中女性标记（女、妃、太后、婉儿等）→ 女雷神，命中男性标记（帝、王、将军、法师等）→ 云舟；判断不出且无人物时用默认音色；
- 流水线用 `resolveNarrator(persona)` 取名后调 `synthesize(text, { speaker })`；指定音色合成失败（账号权限、音色下线）自动回退默认音色重试一次，避免整幕无声；
- 讲述人身份同时决定文稿口吻（§4.2）与配音音色；默认「现代导游」不写 `narrator`，只用默认音色。

**流水线与发布**

- 文稿定稿后，出图、立绘、配音三路并行；逐幕合成写入 `cdn/audio/.tmp-{packId}/scene-{id}.mp3`，元数据 `{ durSec, bytes, sha256 }` 经 `content.json` 落进 `pack.json` 的 `scenes[].audio`；
- 装配与校验成功后，才把暂存目录原子换入 `cdn/audio/{packId}/`（旧目录先挪到 `.old-{packId}`，换入失败回退），失败清理 `.tmp`，保证音频与已发布的 `pack.json` 一致；
- `AUDIO_EAGER_SCENES=0`（默认）全量同步生成；设为前 N 幕时主任务只跑前 N 幕，发布后由 `TaskService` 排 `kind=audio` 任务，`pipeline.topUpAudio` 回读生成源补完剩余幕并重新装配发布（`version + 1`）；`AUDIO_TOPUP=0` 关闭后台补齐；
- `tools/assemble-pack.js` 重装时保留上一版 `scenes[].audio`；`validate-pack.js` 扫描发布目录时跳过 `cdn/audio/`（无 `pack.json` 的目录不当资源包）；
- 存量包缺音频可执行 `npm run audio:backfill -- [包ID...]` 一次性补录，已配音的幕保持原样。

**客户端**

- `loader` 按 `scenes[].audio` 生成 `remoteUrl`（`CDN_BASE/audio/{id}/scene-{id}.mp3`）与本地 `localPath`（`USER_DATA_PATH/audio/{id}/...`）；无元数据时按钮显示「暂无讲解」；
- `core/audio.js` 为全局单例 `InnerAudioContext`，同一时刻只播一幕；本地文件优先、缺失回退 CDN；只在用户点击时播放，切幕或离开页面立即 `stop()`；
- 资源包页下载资源包时自动串行下载该包全部讲解音频（同版本已存则跳过，失败不阻塞打开，可手动重试）；内置包本体随小程序发布、音频仍在 CDN，首次打开时静默后台补存；已下载包仍提供「存音频 / 删音频」，按 `bytes` 与 `sha256` 校验；音频目录独立于包目录，包更新换入时不被清掉，包版本变化时旧音频作废；
- `manifest.json` 不列音频文件，只给每个包附带 `audioCount`（有音频的幕数）用于判断本地包是否为缺音频元数据的旧版；客户端按 `pack.json` 元数据拼接地址。

**测试**：`doubao-provider.test.ts`（流式分片拼接、错误码、音色回退）、`generation-pipeline-audio.test.ts`（装配失败不污染正式音频目录）、`voice-cast.test.ts`（人物映射与称谓兜底），随 `npm test` 执行。

## 6. 健壮性与安全加固（F 类）

发布时间与 API 共用同一 Fastify 进程（`@fastify/static` 挂 `cdn/`）。F2 / F3 / F5 / F6 已落地（见修订记录），下表保留全部条目作为设计与验收口径；仍未完成的只有 F1 与 F4，F1 已并入 0.3 上线前关卡，F4 暂不做。以下改动均不改变生成链路与客户端契约。

| 编号 | 任务             | 优先级 | 问题                                                 | 改动                                                                                               | 验收                          |
| -- | -------------- | --- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------- |
| F1 | 拆分静态发布与任务接口    | P0  | 生成任务打满 CPU 或进程崩溃时静态资源一并不可用                         | `cdn/` 同步到对象存储 + CDN，服务端只跑 API；`CDN_BASE` 与 `API_BASE` 已分离，客户端无需改动                               | 停掉 API 后 manifest 与已发布包仍可拉取 |
| F2 | 发布物完整性校验       | P0  | manifest 无 hash，下载不校验；`loader` 不校验 `schemaVersion` | `cdn-store.ts` 与 `build-manifest.js` 输出 `sha256` + `size`；`cache.js` 校验不匹配即丢弃；`loader.js` 拒绝未知版本 | 截断或篡改素材后提示失败，不白屏            |
| F3 | 已下载包离线可见       | P1  | 列表的已下载区由 `remotePacks` 派生，manifest 失败时为空           | `packs.js` 无条件并入 `cache.listLocal()`，标题与封面读本地 `pack.json`                                        | 断网冷启动可见并打开已下载包              |
| F4 | 按 openid 限流与配额 | P1  | 令牌可被提取，只能按来源限流                                     | `tasks` 加 `user_id`；全局去重不变，限流按用户；CORS 收敛                                                         | 单用户超限 429，其他用户不受影响          |

| 生成源           | `packs-src/{id}/`，生成内容的源目录；同一景点同讲述人原地覆盖，半成品重名才加后缀    |
| 发布物           | `cdn/{id}/`，客户端实际拉取的文件                  |
| 母本（Master）    | `persona` 为空的「景点-导游」版本，供变体作为素材底稿      |
| 人物变体（Variant） | 基于母本改写口吻与讲述视角的版本，同一母本同讲述人唯一 |
| 播音稿（Script）   | 旧包历史字段：带表演标签的口播文本；新包不再生成，讲解音频改由 `scenes[].body` 合成 |
| 讲述人（Narrator） | 第一人称叙述角色，决定口吻、立绘与配音音色                  |
| 生产端           | 检索、编排、生文、配图、打包发布的生成方，即 `server/`     |
