# 热门景点筛选与批量预生成资源包 — 实施计划

## Context

当前资源包全部按用户提交即时生成（检索→大纲→文稿→出图→配音→装配，分钟级）。为热门景点提前批量生成母本包，用户请求命中时走 [task-service.ts](../../server/src/domain/services/task-service.ts) 的 `findExisting` 直接秒回复用；冷门景点仍即时生成。人物变体不预生成（人物是自由文本，组合不可穷举，且现有 `runVariant` 复用母本分镜图本就快）。

**已确认决策**：清单 = 统计参考 + 人工确认文件；执行 = HTTP 客户端脚本（复用服务端去重/队列/清单重建）；只生成母本（persona=''）。

不新增 API 端点，不改 TaskService / domain / infra 任何文件。

## 文件清单（4 新增 + 1 修改 + 1 可选）

| 文件 | 职责 |
|---|---|
| `server/hot-topics.json` | 人工确认的热门清单，批量生成唯一数据源（纳入版本管理） |

| `server/src/scripts/hot-common.test.ts`（可选） | 纯函数单测 |

## 1. 清单文件 `server/hot-topics.json`

```json
{
  "updated": "2026-11-18",
  "cities": [
    { "city": "洛阳", "topics": ["龙门石窟", "白马寺", "洛邑古城", "关林", "老君山", "应天门", "明堂天堂", "洛阳博物馆", "洛阳民俗博物馆（潞泽会馆）", "天子驾六博物馆"] },
    { "city": "郑州", "topics": ["少林寺"] }
  ]
}
```

- `topics` 写裸短名（不带省市前缀/景区后缀），与 `normalizeTopic`（[source-matcher.ts](../../server/src/domain/services/source-matcher.ts)）归一口径一致，去重命中率最高。
- 种子来自 `web/packs/` 内置 10 包对应景点（提交时走 reused 秒回，天然做冒烟验证），其余由 `hot:stats` 首跑后人工补充。
- 维护注意：`normalizeTopic` 只剥洛阳/河南前缀，其他城市景点名须写官方常用短名本身；包含式模糊匹配可能让跨城同名景点误复用，名字要带足够辨识度。

## 2. `hot-common.ts` 纯函数

```ts
export interface HotList { updated: string; cities: { city: string; topics: string[] }[] }
export function parseArgs(argv: string[]): Map<string, string | true>   // --key value / --key=value / --flag
export function loadHotList(file: string): HotList                       // 结构校验，报错带文件路径
export function flattenList(list: HotList): { city: string; topic: string }[]  // 展开 + normalizeTopic 去重
export interface TopicStat { key: string; names: string[]; count: number; done: number; failed: number; reused: number; lastSubmittedAt: number }
export function aggregateGenerateTasks(records: TaskRecord[]): TopicStat[]  // 只取 kind==='generate'，按 normalizeTopic 分组，count 降序→时间降序
export function diffList(list: HotList, stats: TopicStat[]): { listedButNoSubmit: string[]; hotButUnlisted: TopicStat[] }
```

复用：`normalizeTopic` 从 `../domain/services/source-matcher.ts`，`TaskRecord` 类型从 `../domain/types.ts`。

## 3. `hot-stats.ts`

- 读库：`openDatabase(config.dbPath)` → `new TaskRepository(db).listRecent(--limit 默认 2000)` → 内存聚合。不写新 SQL、不加 repository 方法；WAL 多进程并发读安全，migrate 幂等。
- 输出：控制台 Top-N（`--top` 默认 30）：排名/提交数/成功/失败/复用/最近提交/归一名/原始写法样例。
- `--out <file>` 写候选参考 JSON（同清单结构，city 填"待定"），**绝不覆盖 hot-topics.json**。
- 若 hot-topics.json 存在，输出 `diffList` 差异（`--min-count` 默认 3）：清单有但零提交（疑似写错名）、提交多但不在清单（候选补充）。

## 4. `hot-pregen.ts`

参数默认值：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--url` | `http://127.0.0.1:8788` | 服务地址 |
| `--token` | `process.env.API_TOKEN ?? ''` | 非空时 POST 带 `x-api-token`；GET 轮询无需令牌（已核实路由无鉴权） |
| `--list` | `server/hot-topics.json` | 清单路径 |
| `--only` | — | 子串过滤 topic/city，分城市跑批与单挑失败项 |
| `--concurrency` | 2 | 在途任务数（服务端串行消费，≤3 即可） |
| `--poll-ms` | 3000 | 轮询间隔 |
| `--timeout-ms` | 900000 | 单景点超时 |
| `--retry-after-ms` / `--retries` | 10000 / 6 | 429（限流 10/min、队列满 8）退避重试 |
| `--out` | `server/data/hot-pregen-results.json` | 结果落盘，供 `--resume` |
| `--dry-run` / `--resume` | — | 只打印计划 / 跳过结果文件中已 done 条目 |

核心流程：固定 `concurrency` 个 async worker 从共享索引取条目 → `submitTopic`（POST {topic, persona:''}，200→taskId / 429→退避重试 / 400→rejected 不重试 / 401→整体终止）→ `pollTopic` 轮询到 done/failed/timeout，done 按 reused 字段区分计数。每条状态变化打一行进度，结束输出汇总与非成功明细。

幂等：脚本自身不查重，全靠服务端——重跑时 `findExisting` 命中已有包秒回 done(reused)；上次中断时 `findActive` 返回同一 taskId 继续轮询。`--resume` 仅是省 HTTP 往返的优化。

## 5. package.json 入口

```json
"hot:stats":  "node --env-file-if-exists=.env src/scripts/hot-stats.ts",
"hot:pregen": "node --env-file-if-exists=.env src/scripts/hot-pregen.ts"
```

## 6. 验证

1. `npm run typecheck` + `npm test`（含可选 hot-common.test.ts：loadHotList 校验、aggregateGenerateTasks 分组含"洛阳市龙门石窟景区"并入"龙门石窟"、diffList 两段）。
2. 起服务后 `npm run hot:stats` 对现有 app.db 实跑，肉眼核对 Top-N。
3. `npm run hot:pregen -- --only 龙门石窟 --dry-run` → 去掉 dry-run 实跑，预期 reused 秒回。
4. `--only` 一个清单里尚无包的景点真实生成，确认 cdn/ 产出新包且 manifest.json 被 `catalog.reindex()` 自动更新。

## 实施顺序

1. hot-common.ts → 2. hot-topics.json 种子 → 3. hot-stats.ts 实跑核对 → 4. hot-pregen.ts 冒烟 → 5. package.json → 6. 可选单测。

## 已知代价

- 单母本生成数分钟、服务端串行消费：20 个无包景点约 1–2 小时，建议 `--only 城市名` 分批或后台运行。
- 预生成内容固化历史错误风险：依赖 sources.md 复核与 refresh 版本 +1 机制修正（均已有）。
