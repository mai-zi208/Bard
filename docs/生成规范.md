# 资源包生成规范

面向「主题 + 身份 → 可发布资源包」的生成端约定。生产端（智能体或服务）按本规范产出 `content.json` 与配图，再由装配脚本转成 `pack.json` 并通过校验。

对应技术方案 §2.3（文案规范）与 §4（服务端生成）；渲染侧规则见技术方案 §2–3。

## 1. 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `topic` | 是 | 景物名，如「洛阳龙门石窟」。API 入参，用于检索与复用去重 |
| `persona` | 否 | 讲述人身份。API 入参；缺省为「现代导游」：现代口语、无时代限制 |
| `locale` | 否 | 固定 `zh-CN`；生成端只产出默认语言，暂不支持按请求切换 |
| `sceneCount` | 否 | 不是 API 入参；幕数由景物清单决定（5–20 幕），生成默认上限 10，可用 `GENERATION_SCENE_MAX` 调整，校验硬上限 40 |

## 2. 输出目录

```
packs-src/{packId}/
  content.json          文稿契约（生成端唯一文稿交付物）
  sources.md            每幕史实来源（不参与渲染，必须产出）
  images.json           配图来源与原始尺寸（生成端产出）
  cover.jpg             封面原图 3:4
  scene-{sceneId}.jpg   每幕原图 9:16，也接受 png
  narrator-default.jpg  讲述人插画 3:4（生成包整包共用一张）
  narrator-{pose}.png   旧包多姿态立绘（可选）
  sources.json          源图命名例外时的显式映射（可选）
```

装配产物 `pack.json`、`body/{NN}-{sceneId}.md` 与 `NN-{sceneId}.jpg` 写在 `cdn/{packId}/`，不在生成源目录。源图按 `scene-{sceneId}.{jpg,png}` 命名，不要用 `NN-` 前缀；`NN-` 是装配后 `pack.json` 里的包内路径。

`packId` 取景物的通用拼音短名（`longmen`、`baimasi`），全小写、无空格、全局唯一；人物变体为 `{景点slug}--{人物slug}`。

## 3. `content.json` 契约

```json
{
  "id": "longmen",
  "defaultLocale": "zh-CN",
  "title": "洛阳龙门石窟",
  "subtitle": "伊水两岸的千年凿声",
  "summary": "一句话说明这个包带用户看什么。",
  "author": "行迹",
  "tags": ["石窟", "造像"],
  "theme": { "bg": "#16130F", "text": "#F2EBDD", "accent": "#C9A227" },
  "narrator": {
    "id": "wu",
    "name": "武则天",
    "title": "大周圣神皇帝",
    "portraits": { "default": "narrator/wu-default.jpg" },
    "portraitFit": true,
    "portraitMask": true
  },
  "scenes": [
    {
      "id": "yique",
      "title": "伊阙",
      "subtitle": "两山夹一水",
      "imageAlt": "伊水两岸，龙门桥横跨河面",
      "body": "第一块……\n\n第二块……\n\n第三块……\n\n第四块……",
      "transition": "zoom-out",
      "holdMs": 9000
    }
  ]
}
```

**顶层字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `packId`，小写字母/数字/连字符 |
| `version` | 否 | 默认 1；刷新任务 +1 |
| `defaultLocale` | 否 | 默认 `zh-CN` |
| `locales` | 否 | 默认 `[defaultLocale]` |
| `title` | 是 | ≤20 字 |
| `subtitle` | 否 | ≤30 字 |
| `summary` | 否 | ≤60 字 |
| `author` | 否 | 默认「行迹」 |
| `generated` | 否 | 生成流水线写 `true`，装配透传为 AI 生成标识 |
| `tags` | 否 | 2–5 个短标签 |
| `theme` | 否 | `bg` / `text` / `accent` 六位十六进制；缺省用默认主题 |
| `cover` | 否 | 默认 `cover.jpg` |
| `pois` | 否 | ≤20 条，字段见技术方案 §2.2 |
| `ttlDays` | 否 | 覆盖全局保鲜期（默认 180 天） |
| `masterId` / `persona` | 否 | 人物变体用；母本包不写 |
| `narrator` | 否 | 省略时游览页隐藏立绘区 |
| `scenes` | 是 | 5–20 幕；生成默认上限 10，校验硬上限 40 |

**Scenes 字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 幕内唯一 |
| `title` | 是 | 2–4 字（打包上限 12） |
| `subtitle` | 是 | 4–8 字（打包上限 20），不与 title 重复 |
| `imageAlt` | 是 | ≤40 字 |
| `image` | 否 | 不写时装配为 `NN-{id}.jpg`；源图仍按 `scene-{id}.{jpg,png}` 命名 |
| `images` | 否 | 正文内嵌图路径数组 |
| `body` | v2 是 | 单页 Markdown，固定 4 块，块间空一行 |
| `paragraphs` / `pages` | 否 | 仅旧包兼容，新生成包不写 |
| `pose` | 否 | 讲述人动作，≤20 字；仅供人物变体复用，不写入 `pack.json` |
| `transition` | 否 | `zoom-out` / `rise` / `slide` / `fade` |
| `holdMs` | 否 | 8000–10000 |
| `narratorPose` | 否 | `default` / `explain` / `point` / `think` |
| `portrait` | 否 | 旧包按幕插画，新生成包不写 |

**Narrator 字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 小写字母/数字/连字符 |
| `name` | 是 | ≤8 字 |
| `title` | 否 | ≤12 字 |
| `portraits` | 否 | 至少 `default`；生成包为 `narrator/{id}-default.jpg` |
| `portraitFit` | 否 | `true` 时完整显示不裁切 |
| `portraitMask` | 否 | `true` 时四边羽化 |
| `poses` | 否 | 旧包多姿态 PNG 立绘，新生成包不写 |

- 展示类字段均为本地化字段，支持纯字符串或本地化对象；生成端只产出 `defaultLocale` 的纯字符串。
- `body` 可写内联 Markdown（含换行）或相对路径；生成端推荐内联，装配脚本统一落盘为 `body/{NN}-{sceneId}.md`。
- `layout` 不由生成端写；渲染端按单页 Markdown 自行排版，不再按字数推导。
- 新包不写 `narration` / `audioLabel` 口播稿字段；讲解音频由 `scenes[].body` 直接合成，`scenes[].audio` 只存 `{ durSec, bytes, sha256 }` 元数据。

## 4. 文稿规则

原则：站在听众的角度写听众感兴趣的内容。

举例：内置「洛阳白马寺」讲解包，一物一幕，每幕四段；第一段简要概括看到的东西，第二、三段给来历与人事，第四段收一句与讲述人相关的短点评，或干脆停在事实上。

### 4.0 范式：每段只干一件事

以内置白马寺山门幕为基准样本（四段，合计 168 字）：

> 这里是白马寺的山门。正中的「白马寺」匾，由中国佛教协会原会长赵朴初题写。
>
> 山门开三个门洞，象征佛教的「三解脱门」：空门、无相门、无愿门。跨过这道门，就是把执念放下。
>
> 山门前那两匹石马，传说是汉代驮经之马。其实是北宋太师魏咸信墓前的石像，民国二十四年被移到寺前。
>
> 白马寺始建于东汉永平十一年，公元六十八年，是佛教传入中国后兴建的第一座官办寺院。

| 块     | 必须写到                          | 反例（不要这样写）                   |
|-----|----------------------------|---------------------|
| 第 1 段 | 你能看到的但听众不了解的东西：匾、造像、石马、碑      | 「伊水从两山之间穿流而过，远望像一座天然门阙」——只有地理，没有可指认的东西    |
| 第 2 段 | 这件实物的故事：谁、何时、为什么，或它象征什么、发生过什么 | 「三座洞窟并列开凿，中洞的窟顶做成华盖的样子」——只描述外形，没有故事，也没有原因 |
| 第 3 段 | 一条「人事」：谁在这里做过什么；传说与史实的分别      | 「中洞有三世佛造像，岩壁上布满彩绘浮雕」——罗列造像配置，听完记不住        |
| 第 4 段 | 一句短点评，或一条能记住的关键事实             | 「耳长一点九米，比人还高」——同一「比…还…」句式在整个包里反复出现        |

验收只有一句话：四块连起来读，应当像一个人站在你面前，指着东西讲故事；如果读起来像景点介绍牌或百科条目，就是没写对。

### 4.1 景物清单决定幕数

不预设幕数。先按真实步道顺序列出可讲的实体——殿、窟、碑、塔、井、树、遗址都算：

- 一物一幕，幕数 = 清单长度，5–20 幕；生成默认上限 10（`GENERATION_SCENE_MAX` 可调），超过上限按片区拆包；
- 只剩遗址、无实物可看的不单独成幕，并入相邻幕一句话带过；
- 清单须覆盖主要景物。允许为叙事节奏合并同类小物件，不允许为了凑固定幕数而丢弃景物；
- 顺序与真实游览路线一致（由外到内、由南到北）；首幕交代位置与来历，末幕落在清单里最有分量的实体上。

### 4.2 段与块（固定格式）

文字单元是「段」，即一个自然段；新生成包一律按固定格式写，不做条目化排版。

| 层 | 规则 | 说明            |
|---|---|---|
| 段 | 30–48 字（含标点） | 一块讲一件事，段内不换话题 |
| 屏 | 同屏两块 70–90 字 | 第 1–2 块为第一屏，第 3–4 块为第二屏 |
| 幕 | 4 段，合计 150–170 字 | 一物一幕，四段连排为一页；白马寺 8 幕实测 34–47 / 74–88 / 155–168 |

- 客户端默认露出前 3 块、上拉拉出第 4 块；
- 单块、同屏、全幕三道字数闸门同时生效，不允许靠拉长某一块去凑整幕字数；
- 生成侧首轮按上表校验；字数不达标时只把不达标的幕放宽到单块 25–50 字（同屏 60–100 字、全幕 140–180 字）重写，其余幕沿用原稿；仍不达标则记警告、按实际输出继续，字数不再阻断发布；块数仍严格校验（必须 4 块）；
- 装配校验只对低于 150 字的正文告警；150–170 的块结构由生成端把关，存量短文包只告警、不阻断发布。

单幕四段按「客观 → 客观 → 客观 → 主观或事实收束」推进：

| 块序    | 取材                            |
|-----|------------------------------|
| 第 1 段 | 可视实物：站的地方能看到的东西；第一句就落到一个能指认的实物 |
| 第 2 段 | 来历、故事或象征：谁、何时、为什么、故事，或这处实物象征什么 |
| 第 3 段 | 一条人事：谁在这里做过什么；传说与史实分开写         |
| 第 4 段 | 短点评，或一条能记住的关键事实                |

第 2、3 段至少要有一块写「人事」。两块都只描述外形、造像配置或保存状况，这一幕就成了资料卡。

主观只占一块，必须挂在前面某条事实上，说明它为什么值得看；只有与讲述人有明确历史关联的幕才写本人视角，其余幕用客观叙述或引用有出处的他人说法。没有明确关联的幕，第 4 块直接停在事实上。

客观块内部不设模板：从哪个信息位切入、先给现状还是先给事件，由内容决定。第 1 块通常交代「此刻看得见什么」以建立方位，但不得每幕用同一种句法开头。

### 4.3 散文化

- 句长必须参差，每块至少一句 ≤10 字；
- 允许不完整句、名词收尾、口语插入（「其实」「说白了」）；
- 不写对仗句式，不写三项排比，不写「不仅…而且」「既…又…」；
- 每屏形容词汇总 ≤2 个，禁用「巍峨」「庄严」「精美」「震撼」「令人叹为观止」这类套语；
- 不使用第二人称说教（「你不妨想想」「你抬头的时候」）；
- 每屏至少一个可触摸的具体细节：一道凿痕、一行题记原文、一处磨损、一个可核验的年份；
- 第 1 块第一句必须落到具体名词（实物、人名、地名、动作），不得用「XX 是……」这类定义句或「规模最大」这类概括开头；
- 不写尺寸（高、宽、进深、通高多少米）与数量清单（多少尊、多少块、多少种、多少例）；年代、门洞数、人数这类支撑叙事的数字可以写，同一件事的一组数字算一处，每块至多一处；
- 全包「X，比 Y 还 Z」这类比喻最多出现一次，且不得连续两幕用比喻收尾。

生成端对本节规则做机械复核：命中尺寸数据、同块数量清单（≥2 处）、套语或「比…还…」超配额时，把问题清单回喂模型重写一次；仍不达标只记警告、不阻断发布。字数另有「严格 → 放宽 → 兜底告警」三档，见 4.2。

### 4.4 开头与收尾必须轮换

开头可选：画面切入、动作切入（「沿栈道往里走」）、数字切入、否定切入（「这里没有…」）、引文切入。

收尾可选：停在实物细节、停在未完成、停在题记原文、停在人物原话、干脆不收（最后一句仍是事实）。

- 同一包内不得连续两幕使用同一类开头或收尾；
- 主观块的来源要轮换：本人评述、旁人说法、古人引文三类别连续复用；引用他人或古人时须标明出处或说话人（「《洛阳伽蓝记》里写…」「旁边的导游说…」），不得含混成本人口吻；
- 主观合计约占全文两成；与讲述人无明确历史关联的幕不写主观，第 4 块直接停在事实上；
- 禁止每幕都以「对举 + 留白」的短句升华收场。

### 4.5 事实纪律

- 每幕至少一条可核验史实，并在 `sources.md` 记录出处；无法核实的细节一律删掉；
- 写人优先：同样能说明问题时，写「谁在这里做过什么」胜过写「现存多少、高多少」；
- 讲述人关联优先：有讲述人时，优先采用与其有明确关联的实体与事件，整包至少两幕用上；资料里没有关联就写客观事实，不得编造关联；
- 不写百科腔：不得连续两块以定义句（「XX 是……」）开头，不把「世界文化遗产」「规模最大」「艺术宝库」这类概括当成内容；
- 不写尺寸（面阔、进深、通高、长宽）、不写建筑形制术语（歇山、悬山、硬山、斗拱铺作）、不写历代重建年份；年代只保留与讲解直接相关的一两个；
- 数字（年代、数量）必须来自检索结果，不得估算或四舍五入成整数，并写成中文读法（「公元六十八年」「民国二十四年」）；
- 讲述人若为历史人物，不得出现晚于其亲历年代的表述，不得让其评价未发生的事；
- 不出现夸张营销语（「震撼」「必打卡」）与推销口吻；
- 专有名词首次出现给全称，如「奉先寺（大卢舍那像龛）」；
- 每幕标题 2–4 字，副标题 4–8 字，二者不重复。

### 4.6 成稿自检清单（通用）

以下口径对新建包与改稿同样生效，每幕写完逐条过一遍；任一条不满足就改该块，不改幕结构。数量指标只在 4.2 的「严格」档生效，进入放宽档后按 4.2 的规则仅记警告。

| 项 | 判定 |
|---|---|
| 幕数 | 等于景物清单长度，5–20 幕，不为凑数增删景物 |
| 幕内结构 | 4 块，不增不减、不跨幕合并 |
| 单块字数 | 30–48 字（含标点） |
| 同屏字数 | 70–90 字（第 1–2 块、第 3–4 块） |
| 全幕字数 | 150–170 字 |
| 客观与主观 | 客观三块、主观至多一块，主观约占两成 |
| 主观资格 | 只在本幕与讲述人有明确历史关联时写本人视角；无关联则第 4 块停在事实上 |
| 第 1 块 | 首句落到可指认的实物，不用定义句、不用「规模最大」类概括 |
| 人事取材 | 第 2、3 块至少一块写「谁、何时、做了什么」 |
| 冗余清理 | 尺寸、建筑形制术语、历代重建年份一律删；年代只留与讲解相关的一两个 |
| 数字 | 全部来自检索结果，中文读法，每块至多一处 |
| 套语 | 无「巍峨／庄严／精美／震撼」等形容词堆叠，每屏形容词 ≤2 个 |
| 开头与收尾 | 与相邻幕不同类，不连续复用同一句式 |
| 标题 | 标题 2–4 字，副标题 4–8 字，二者不重复 |

写作顺序固定为：列景物清单 → 定幕数 → 逐幕按四块取材 → 清理冗余 → 过本清单。四块连读应当像一个人站在面前指着实物讲故事；读起来像景点介绍牌或百科条目，即为不通过。装配校验只对低于 150 字的正文告警，150–170 的块结构由生成端把关。

### 4.7 白马寺文稿制作示例

```
输入：topic=洛阳白马寺，persona=武则天
1. 列景物清单：山门、天王殿、大佛殿、大雄殿、接引殿、清凉台、齐云塔、国际佛殿苑，共 8 幕；
2. 逐幕按四块取材。以山门为例：匾额与石马 → 三解脱门 → 石马来历与传说辨析 → 永平十一年建寺；
3. 字数自检：四块 36/45/47/40 字，两屏 81/87 字，全幕 168 字；
4. 清理冗余：删去「中国第一古刹」这类概括，保留赵朴初题匾、三解脱门、石马年代、永平十一年四个可核验点；
5. sources.md 对应记录：
```

## 5. 配图规则

配图顺序固定为「先文稿、后出图」：每幕正文写定后产出 `imageAlt`，出图服务（千问 `qwen-image-2.1-pro`，竖图 1024×1536）按它逐幕生成；出图与绘制立绘、逐幕配音三条分支并行，出图 6 路并发、单幕失败隔 2 秒重试一次，谁先产出谁先写入包目录，最后统一转换、校验并原子发布。配音默认全量同步生成（`AUDIO_EAGER_SCENES=0`）；若配置为只同步前若干幕，其余幕在包发布后由后台 `kind=audio` 任务逐幕补齐 MP3、回写 `audio` 元数据，全部补完再整体发布 `version + 1`，不阻塞出包与首次展示。

- **景物配图必须对应文稿内容**：配图画的就是正文指认的主体（门、殿、坊、冢、亭），出图提示词不得引入正文没有的殿、塔、碑、树；画面有多处时以正文主体居中；
- `imageAlt` 由大纲产出，≤40 字，只描述要画出来的实物与场景，不写尺寸、文字与水印；文稿阶段可回写更贴画面的描述；
- 画面里的天气、光线、树木只作背景交代，不当史料写；
- `imageQuery` 已废弃：配图不再检索，文稿阶段不再产出该字段；
- 封面 3:4，900×1200，JPG，≤200KB；
- 每幕 9:16，宽 1080，JPG，≤400KB；超限先降质再考虑裁切；
- 正文内嵌图宽 ≤1080，单张 ≤300KB，同一幕合计 ≤600KB；
- 一幕多屏时共用一张主图，不按屏配图；画面不出现文字、水印、拼贴；
- 生成图为 1024 宽，装配时允许在 9:16 中心裁切后等比例放大到 1080；放大仅用于分镜，不用于封面；
- 出图服务未配置或返回失败时任务直接失败并报错，不用占位图凑数；包级用 `generated: true` 标识 AI 生成内容；
- 每张配图都要在 `images.json` 记录 `provider`（`generated` / `linked`）、`sourceUrl` 与原始宽高；`sources.md` 同步记录图源，便于溯源与替换。

## 6. 装配与校验

```bash
node tools/assemble-pack.js --content packs-src/longmen/content.json \
     --assets packs-src/longmen --out cdn/longmen
node tools/build-manifest.js
```

传 `--assets` 时，装配脚本按顺序执行：`content.json` → `pack.json` → `convert-assets.py`（缩放转 jpg / png）→ `validate-pack.js`。退出码非 0 即失败，不得发布。

校验闸门（缺一不可）：

1. 结构：`validate-pack.js` 0 错误；
2. 体积：内置包 ≤5MB、在线包 ≤10MB（校验脚本 5MB 告警、10MB 报错）；
3. 史实：`sources.md` 覆盖全部幕（人工/编辑器检查，校验脚本不自动判定）；
4. 合规：AIGC 内容带生成标识（`generated: true` 自动写入）并通过内容安全检测（P5 接入前人工把关）。

## 7. 失败语义

| 情况 | 处理 |
|---|---|
| 检索不到可核验资料 | 任务失败，返回「资料不足，暂不支持该景物」，不生成残缺包 |
| 校验报错 | 退回文稿/配图环节重做，不发布半成品 |
| 图片缺失或命名不符 | 装配中断，按报错补 `sources.json` 或改名 |
| 主题已存在 | 进行中任务直接复用；已发布包在生成源未更新时复用既有 `packId`，生成源更新则重新装配 |
